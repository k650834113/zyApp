# 正式需求基线 v2（PC 优先）

> 本文件记录已确认的新需求边界；既有 PC 经营、财务、同步与小程序正式基线继续以现有规格、验收记录和开发路线图为准。

## 2026-08-23：小程序桌游库排序

- 桌游库首页不再显示“已展示 N 款桌游”的结果数量文案。
- 桌游库默认按桌游主档首次录入库的创建时间倒序展示“最近更新”，不使用资料修改时间，也不受点赞操作影响；可切换为按门店点赞总数倒序展示“最多喜爱”。排序入口使用下拉菜单，菜单不提供年份排序。切换排序后清空当前列表、回到页面顶部并从第 1 页重新加载；排序必须在服务端分页前完成，筛选、搜索和下滑增量加载继续沿用同一排序。
- 2026-08-23 已将语义修正后的生产 API 候选 `a5b93b2cc53f8f2541975867eb4378bcd44edcc0` 部署到 `https://judian.icu`；“最近更新”前 24 条已与生产库按 `created_at DESC` 计算的结果逐项比对一致，“最多喜爱”点赞数顺序与两种排序差异均已验证，生产备份、迁移 21 和双环境隔离保持正常。

## 2026-08-23：小程序只保留正式发布通道

- 小程序移除 `test-wechat` 和 `production-test-wechat`，开发版、体验版、审核版和线上版都使用同一份 `production-wechat` 产物。
- 可上传产物只允许访问 `https://judian.icu` 和正式门店，构建器继续拒绝 HTTP、IP 地址、`/test`、Mock 支付、开发会话和非正式门店。
- 删除小程序测试 API/门店配置入口和虚拟手机号登录入口；Mock 和 `development-http` 仅作本地开发，不得用于微信上传。
- 正式小程序从 `1.1.0` 开始按该单一通道继续迭代，上传前必须执行 `corepack pnpm miniapp:build:production`。

## 2026-08-21：小程序集成桌游工具箱

- 正式小程序新增游客可直接使用的“工具”一级入口，底部导航统一为“首页 / 桌游库 / 工具 / 明细 / 我的”；工具均为纯本地能力，不要求登录或联网，不上传玩家和对局数据。
- 首批固定交付先手玩家、玩家分队、快速骰子、抛硬币和计分器五项核心工具。每项工具使用独立页面和大触控区，提供清晰的结果反馈与一键重来，避免把多个操作挤在同一屏。
- 先手玩家在真机支持至少两人同时按住屏幕并在稳定约 1 秒后随机选出一人，每个触点即时获得不同颜色，手指轻微拖动仍按触点身份连续识别，同时提供单指依次添加点位的兼容模式；玩家分队先指定 2–6 队，再由多人同时按住屏幕并直接以触点颜色显示平衡分队结果。
- 快速骰子支持在总计 1–6 枚范围内自由组合 D4/D6/D8/D10/D12/D20（例如 1D4+2D6），点击结果区触发滚动动画；抛硬币提供动画、声音、震动及正反面分别统计；计分器改为 1–8 人的可增列、可增行表格，单格支持正负数和小数，底行实时合计并在本机续局。
- 工具主页的每项入口只展示原创功能图形和工具名称，不再显示说明文案。
- 随机能力不调用后端，不改变会员、钱包、月卡、支付、桌游库存或云同步合同；真机验收需覆盖多点触控、震动反馈、安全区和计分续局。

## 2026-08-20：本地封面补传、扩展搜索与冲突降噪

- PC 选择本地桌游封面后，在云端可用时先上传到 ZyApp 自有封面缓存，再把公网缓存 URL 与受控本地路径一并保存；既有仅含本地路径的桌游在店长登录并同步时分批自动补传，保证其他 PC 与小程序可读取同一缓存 URL。断网时仍允许保留本地文件，重连后继续补传。
- PC 将桌游标记为扩展时，所属基础游戏选择器提供按中文名称即时筛选，并始终保留当前已选基础游戏，避免桌游库较大时逐项翻找。
- 桌游与公告的普通并发版本冲突属于非资金内容冲突，重连时默认采用云端版本并记录自动处理审计，不再长期累积在冲突数量中。
- 会员、收费目录、活动、门店资料、员工权限以及任何内容异常仍要求店长人工合并；钱包、月卡、订单、支付、退款等资金与账务事实绝不自动覆盖。重连后仍存在人工冲突时，PC 全局弹窗提醒并跳转到云端资料合并页。

## 2026-08-19：正式小程序桌游库浏览优化

- 正式小程序桌游库首页只展示基础游戏，不再把扩展混排或原地展开；有扩展的基础游戏在卡片内部右下角显示“+N个扩展”，点击进入仅展示其直接扩展的独立页面，并使用微信原生返回回到基础游戏库。
- 基础游戏库和扩展页均按 24 条一页增量加载，下滑时继续请求下一页，不一次载入全部桌游。
- 桌游卡片默认显示前三个标签，其余标签用“…”提示，不再额外显示“点击查看详细信息”；点击卡片后展示完整标签和简介。
- 桌游库主页搜索只对桌游名称做模糊匹配；标签筛选默认展示最常用的 12 个标签，独立标签搜索栏按输入内容模糊显示可勾选的匹配结果；点击任一桌游卡片上的标签可直接跳转到应用该单标签筛选的桌游库页面。

## 2026-08-14：桌游标签统一为集石中文词表

- PC 与小程序的桌游标签统一采用集石详情中的风格/分类、模式、主题和机制中文词条；按页面顺序合并、去重后保存为一个扁平数组，不在产品界面拆分组别。
- BGG 继续提供名称、人数、时长、复杂度和封面等基础资料，但不再自动填充或覆盖标签；新增/编辑时标签必须由店长按集石中文词表确认。
- 单款桌游最多允许 30 个扁平标签，以完整容纳集石详情；单标签仍限制为 40 个字符。
- 2026-08-14 已完成生产库 399 款桌游全量审查和重写：旧词表 106 个，新集石词表 188 个，399 条领域更新均生成审计和 outbox，并已全部获得云端确认；小程序公开接口 399 条逐 ID、逐标签一致。
- 本轮使用负责人账号已登录集石应用中的可见详情页、应用内公开搜索结果和此前留存的完整详情快照进行一次性数据审查；没有调用集石非公开接口，也不改变“未获公开授权 API 前不建立自动集石集成”的边界。

完整数据范围、备份、事务、同步和验收结果见 [桌游集石标签统一验收](./0.24.1桌游集石标签统一验收.md)。

## 2026-08-13：桌游扩展库存与小程序分组决策

- 桌游库存主档增加可空的所属基础游戏；为空表示基础游戏，有值表示扩展。
- 扩展只能关联同商户的基础游戏，禁止关联自身、扩展套扩展，以及把已有扩展子项的基础游戏改为扩展。
- PC 新增/编辑桌游时，在编辑器顶部的“游戏类型与归属”选择“基础游戏”或“扩展”；扩展必须显式选择所属基础游戏后才能保存。
- 本地 SQLite、同步事件、云端 PostgreSQL 投影和小程序公开 DTO 统一传递该关系。
- 小程序桌游库首页只展示基础游戏；有扩展的基础游戏在卡片右下角显示扩展入口，点击后进入仅展示其直接扩展的独立分页页面，使用微信原生返回回到基础游戏库。

## 2026-08-02：小程序桌游库增补决策

本迭代交付范围固定为：

- 云端 PostgreSQL 保存可空的数字复杂度，并保存按门店、桌游和微信查看者隔离的点赞关系。
- 顾客桌游 API 只返回当前门店实际可玩的桌游，并支持名称、分类、人数、时长和复杂度筛选。
- 小程序新增“桌游库”与“我喜欢的”页面、四项底部导航、共享桌游卡片、展开简介和点赞/取消点赞。
- Mock 数据和自动化测试覆盖本轮页面、筛选、点赞与收藏合同。

以下内容不在本迭代中实现：

- PC 端桌游库存或资料录入界面的修改。
- PC SQLite 数字复杂度字段、迁移及校验。
- PC 与云端之间的数字复杂度同步合同和同步实现。
- 真实桌游复杂度的查询、人工录入、批量回填及生产数据核对。

本功能在自动化实现完成后仍不得直接视为已正式发布。生产放行必须同时满足：

1. 所有公开且实际可玩的桌游均已填写并复核 `0.0–5.0` 数字复杂度。
2. 测试 API 已部署对应云数据库迁移和新接口。
3. 微信体验版已完成真实账号、真实门店数据与真机交互验收。
4. 负责人明确批准生产发布。

详细交互、筛选语义、接口和人工验收清单见 [小程序桌游库、筛选与点赞设计](./superpowers/specs/2026-08-01-miniapp-board-game-library-design.md)。

## 2026-08-03：PC 桌游快速录入与 BGG 导入决策

下一迭代补齐 PC 到小程序的桌游资料闭环：

- PC、SQLite、同步协议和云端投影统一增加 `0.0–5.0` 数字复杂度，公开小程序继续只读取现有 `PublicBoardGameSummary`。
- 店长可按名称、BGG ID 或 BGG 链接搜索候选，并自动带入人数、时长和复杂度；按 2026-08-14 决策，BGG 分类不再写入标签字段。
- 中文名称、中文简介和集石中文标签必须由店长确认；不自动翻译、改写或公开 BGG description。
- BGG 通过云端服务端适配器访问，Token 不进入 Electron、SQLite、小程序、安装包或 Git；未获批或不可用时保留完整手工录入。
- 集石在没有公开授权 API 前不接入，不抓取网页或调用非公开接口；未来只通过相同元数据适配器边界扩展。
- BGG 候选只填充编辑器，店长确认保存后才在同一 SQLite 事务中写入主档、门店配置、审计和 outbox。

BGG Commercial Application 已于 2026-08-06 审核通过，服务端 Token 的真实搜索请求返回 HTTP 200。Token 只允许以服务器只读密钥文件部署，不进入环境变量值、Electron、SQLite、小程序、安装包、日志或 Git。

负责人已批准测试和生产启用 BGG 文字与数值元数据搜索；公开图片授权范围尚未单独确认，因此 `BGG_PUBLIC_IMAGES_ENABLED=false`，PC 继续支持本地图片。生产放行仍要求测试环境先完成真实搜索、详情导入、中文字段人工确认、迁移 20、跨端同步及更新通道验证。

完整范围、字段、错误降级、许可门禁和验收清单见 [PC 桌游快速录入与 BGG 元数据导入设计](./superpowers/specs/2026-08-03-pc-board-game-entry-bgg-import-design.md)。

## 2026-08-11：PC 独立桌游管理与 BGG 封面缓存决策

负责人确认下一轮 PC 桌游管理改造采用以下范围：

- 修复 BGG 搜索结果只含 alternate name 时整个查询失败的问题。
- 桌游管理从内容管理中独立，采用每款约 100px 高的舒适单行列表；原内容管理仅保留公告。
- 新增/编辑桌游使用宽版分栏弹窗，持续展示封面、BGG 候选和结构化字段。
- BGG 详情返回图片 URL 供未保存编辑器预览；保存时必须先由 ZyApp 服务端下载、校验并缓存封面，再把 ZyApp 自有 URL 写入本地事务、outbox 和云端投影。
- BGG 封面缓存失败时保留表单，允许重试、改用本地图片，或由用户明确选择默认占位图后保存；禁止静默保存 BGG 直链。
- 已保存记录在 PC 和小程序中只访问 ZyApp 缓存 URL；保存前编辑器可直接预览 BGG URL；无图片记录统一由客户端渲染默认占位图。
- 测试与生产使用独立持久卷，缓存能力通过真实测试环境验收后再启用生产图片开关。

完整交互、数据流、安全边界和验收清单见 [PC 独立桌游管理、BGG 修复与封面缓存设计](./superpowers/specs/2026-08-11-pc-board-game-management-bgg-cover-cache-design.md)。

## 2026-08-12：BGG 封面图片授权与生产启用确认

负责人明确确认现有 BGG 商业授权允许 ZyApp 获取、缓存并在 PC 与小程序中展示 BGG 封面图片。按测试先行门禁完成真实卡坦岛封面的详情解析、HTTPS 下载、图片签名与媒体类型校验、测试/生产独立持久卷写入、公开 URL 回读和 SHA-256 一致性验证后，测试与生产均启用 `BGG_PUBLIC_IMAGES_ENABLED=true`。保存业务记录时仍只允许写入 ZyApp 自有缓存 URL，禁止持久化 BGG CDN 直链，并继续展示 `Powered by BGG` 署名。
