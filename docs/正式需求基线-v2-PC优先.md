# 正式需求基线 v2（PC 优先）

## 2026-10-18：小程序工具箱自定义转盘

- 游客可添加、编辑及删除项目，填写名称和正整数数量；每份数量对应一个等分扇区，同一项目可占多格。单次最多12个项目、60格。
- 点击开始持续旋转，再次点击停止后减速停在随机扇区；每格概率相同，命中扇区和对应项目行高亮，并展示项目名称。旋转和减速期间锁定配置，离开页面停止动画。不涉及后台或抽奖奖品库存。

## 2026-10-16：活动展示调整

- 活动素材由PC“小程序控制 → 活动海报”配置并发布：独立的横向封面用于首页轮播、近期活动和活动列表，详情海报用于详情原比例展示。活动标题、摘要、正文和起止时间仍由“活动发布”维护。
- 小程序只读取当前门店已发布的coverUrl，不按活动ID或标题映射内置素材；未配置封面时显示通用活动卡面，不能回退裁切详情海报。封面替换不需要重新上传小程序代码。
- coverUrl沿用现有装修JSON、门店素材归属校验、草稿、版本冲突、幂等发布及历史恢复流程；旧配置缺字段继续有效，不新增数据库迁移。

- 首页默认头图始终保留，与已发布且正在进行的活动共同轮播；活动到期后退出轮播。
- 首页活动轮播、近期活动缩略图与活动列表使用简洁活动卡面，不裁切完整海报作为封面；卡面展示短标题、状态和日期，完整规则在详情中展示。
- 活动详情按原比例展示完整海报，移除活动收费；没有真实约局关联时不显示参与方式、关联约局及查看约局按钮。当前活动合同无约局关联字段，不以全店约局列表替代关联约局。

## 2026-10-14：小程序好友、同桌与共享对局

- 关于门店移除Logo和实景照片；收费说明增加“单次充值满500元，即可永久享受会员价。”，500元包含边界值，仅改展示文案。
- 先手锁定后按选中玩家颜色染背景、强化选中圆环并淡化其他触点；计分器强化清空分值按钮，保留确认与玩家资料。
- 新计分表默认仅当前登录会员一人，读取昵称与头像；恢复旧表保留原内容。清空分值移到添加回合旁，保留玩家；添加临时玩家与好友、同桌码、扫码按钮同级。“结束并重置”弹窗选择保存对局或直接重置，保存成功才重置，失败或取消编辑保留计分表；重置回本人一人并移除本机同桌关联。扫码确认只导入昵称与头像，由发起者计分，不实时同步各手机分数。同桌最多8人，创建后24小时过期，可主动关闭。
- “我的”仅保留一个“我的好友”入口；好友页右上角使用二维码和扫一扫图像按钮，保留原有扫码和名片功能。
- 好友双方确认，入口为扫码名片、同桌申请和准确会员编号搜索；不公开手机号和财务资料。临时昵称仍可代录，不按姓名自动绑定会员。
- 新对局可关联创建者的已确认好友或有效同桌会员，自动进入关联会员记录；仅创建者与关联参与者可访问，创建者负责编辑，各人只能隐藏自己的记录。隐藏状态不因编辑或移除后重新加入而恢复。本条取代2026-09-11对“新对局不绑定他人账号”的限制；旧记录仍保持原私密范围。
- 记分开关独立于单人胜利、多人胜利或排名。胜者手选，支持全员平局；自动高低分排名即时更新，竞赛并列为1、1、3；不记分时可手动排名。
- 团队共享同队得分、结果和名次，按队伍排名；合作共享全局得分及胜利/失败/平局。队伍、得分和结果统一在玩家成绩表格编辑。字段错误显示具体位置、红框和就地说明。
- 继续采用NestJS、PostgreSQL、共享合同、门店权限、幂等命令及版本冲突检查。无实时多人计分、公开对局分享或新增微信订阅通知。
- 实施与部署交接见[本轮修改交付说明](./miniapp-upgrade-20260910/12-好友同桌与对局修改-20261014.md)。本轮源码和正式构建不等于后台部署、微信上传或真机验收。


## 2026-10-14：按名称和地址设置到店导航

- PC“小程序控制 → 门店介绍”以城市、门店名称和详细地址搜索地图登记地点，不要求店长输入经纬度。候选显示名称、地址和地图来源，由店长选择正确地点，再按现有草稿与发布流程生效。

## 2026-10-05：PC读取小程序当前内容

- 读取不修改云端草稿；编辑后仍需保存草稿再发布，保留门店权限、版本冲突校验、幂等与发布历史。云端已有其他草稿时，覆盖前由PC明确提醒。
- 收费展示项目从真实有效的 admission 收费配置中自选，价格自动填入，发布前校验价格与当前门店配置一致；月卡价格和期限单独读取月卡配置。展示选择不改变收银和月卡规则。
- 旧API不提供当前内容快照时，PC明确提示需要更新API，不将仅有装修配置冒充完整实际内容。

## 2026-10-04：小程序品牌与门票展示

## 2026-09-11：小程序约局、对局与验收补充

- 本店约局到店结算，无押金、不保证桌位；截止前可加入或退出，发起人可取消；已有报名后修改游戏/时间需取消重建，暂不做踢人和爽约处罚。报名截止仍未满员自动取消，满员保留。

- 工具主页的每项入口只展示原创功能图形和工具名称，不再显示说明文案。

## 2026-08-02：小程序桌游库增补决策

本迭代交付范围固定为：

- 云端 PostgreSQL 保存可空的数字复杂度，并保存按门店、桌游和微信查看者隔离的点赞关系。
- 顾客桌游 API 只返回当前门店实际可玩的桌游，并支持名称、分类、人数、时长和复杂度筛选。
- 小程序新增“桌游库”与“我喜欢的”页面、四项底部导航、共享桌游卡片、展开简介和点赞/取消点赞。
- Mock 数据和自动化测试覆盖本轮页面、筛选、点赞与收藏合同。

以下内容不在本迭代中实现：

- PC 端桌游库存或资料录入界面的修改。
- PC SQLite 数字复杂度字段、迁移及校验。
- PC 与云端之间的数字复杂度同步合同和同步实现。
- 真实桌游复杂度的查询、人工录入、批量回填及生产数据核对。

本功能在自动化实现完成后仍不得直接视为已正式发布。生产放行必须同时满足：

1. 所有公开且实际可玩的桌游均已填写并复核 `0.0–5.0` 数字复杂度。
2. 测试 API 已部署对应云数据库迁移和新接口。
3. 微信体验版已完成真实账号、真实门店数据与真机交互验收。
4. 负责人明确批准生产发布。

详细交互、筛选语义、接口和人工验收清单见 [小程序桌游库、筛选与点赞设计](./superpowers/specs/2026-08-01-miniapp-board-game-library-design.md)。

## 2026-08-03：PC 桌游快速录入与 BGG 导入决策

下一迭代补齐 PC 到小程序的桌游资料闭环：

- PC、SQLite、同步协议和云端投影统一增加 `0.0–5.0` 数字复杂度，公开小程序继续只读取现有 `PublicBoardGameSummary`。
- 店长可按名称、BGG ID 或 BGG 链接搜索候选，并自动带入人数、时长和复杂度；按 2026-08-14 决策，BGG 分类不再写入标签字段。
- 中文名称、中文简介和集石中文标签必须由店长确认；不自动翻译、改写或公开 BGG description。
- BGG 通过云端服务端适配器访问，Token 不进入 Electron、SQLite、小程序、安装包或 Git；未获批或不可用时保留完整手工录入。
- 集石在没有公开授权 API 前不接入，不抓取网页或调用非公开接口；未来只通过相同元数据适配器边界扩展。
- BGG 候选只填充编辑器，店长确认保存后才在同一 SQLite 事务中写入主档、门店配置、审计和 outbox。

BGG Commercial Application 已于 2026-08-06 审核通过，服务端 Token 的真实搜索请求返回 HTTP 200。Token 只允许以服务器只读密钥文件部署，不进入环境变量值、Electron、SQLite、小程序、安装包、日志或 Git。

负责人已批准测试和生产启用 BGG 文字与数值元数据搜索；公开图片授权范围尚未单独确认，因此 `BGG_PUBLIC_IMAGES_ENABLED=false`，PC 继续支持本地图片。生产放行仍要求测试环境先完成真实搜索、详情导入、中文字段人工确认、迁移 20、跨端同步及更新通道验证。

完整范围、字段、错误降级、许可门禁和验收清单见 [PC 桌游快速录入与 BGG 元数据导入设计](./superpowers/specs/2026-08-03-pc-board-game-entry-bgg-import-design.md)。

## 2026-08-11：PC 独立桌游管理与 BGG 封面缓存决策

负责人确认下一轮 PC 桌游管理改造采用以下范围：

- 修复 BGG 搜索结果只含 alternate name 时整个查询失败的问题。
- 桌游管理从内容管理中独立，采用每款约 100px 高的舒适单行列表；原内容管理仅保留公告。
- 新增/编辑桌游使用宽版分栏弹窗，持续展示封面、BGG 候选和结构化字段。
- BGG 详情返回图片 URL 供未保存编辑器预览；保存时必须先由 ZyApp 服务端下载、校验并缓存封面，再把 ZyApp 自有 URL 写入本地事务、outbox 和云端投影。
- BGG 封面缓存失败时保留表单，允许重试、改用本地图片，或由用户明确选择默认占位图后保存；禁止静默保存 BGG 直链。
- 已保存记录在 PC 和小程序中只访问 ZyApp 缓存 URL；保存前编辑器可直接预览 BGG URL；无图片记录统一由客户端渲染默认占位图。
- 测试与生产使用独立持久卷，缓存能力通过真实测试环境验收后再启用生产图片开关。

完整交互、数据流、安全边界和验收清单见 [PC 独立桌游管理、BGG 修复与封面缓存设计](./superpowers/specs/2026-08-11-pc-board-game-management-bgg-cover-cache-design.md)。
