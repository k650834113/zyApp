## 自动验证

在仓库根目录依次执行，所有命令必须以退出码 0 完成且不得有失败测试：

```powershell
corepack pnpm test:release-contract
corepack pnpm test
corepack pnpm typecheck
corepack pnpm build
corepack pnpm --filter @zyapp/miniapp test
git diff --check
```

使用被 Git 忽略的本机公开端点配置生成隔离体验版：

```powershell
$config = Get-Content -Raw -Encoding UTF8 E:\AIproject\zyApp\config\public-endpoints.local.json | ConvertFrom-Json
if ($config.miniappTestApiBaseUrl -cne 'https://judian.icu/test') {
  throw '体验版 API 必须严格等于 https://judian.icu/test'
}
if ([string]::IsNullOrWhiteSpace($config.miniappTestStoreId)) {
  throw '体验版测试门店 ID 不能为空'
}
$pcTestStoreId = (Read-Host '从 PC 测试环境“设备与门店设置”复制当前门店 UUID').Trim()
if ($pcTestStoreId -cne $config.miniappTestStoreId) {
  throw 'PC 测试环境与小程序体验版必须使用同一个测试门店'
}
$env:ZYAPP_MINIAPP_MODE='production-test-wechat'
$env:ZYAPP_MINIAPP_TEST_VIRTUAL_PHONE_ENABLED='false'
$env:ZYAPP_MINIAPP_API_BASE_URL=$config.miniappTestApiBaseUrl
```

构建输出必须明确显示 `built production-test-wechat mode`。

## Task 7 发布前预检

部署前必须把下列值保存到同一份验收记录；任一门禁失败即停止 Task 7：

1. 在候选提交上执行以下本地门禁：

   ```powershell
   corepack pnpm test:release-contract
   corepack pnpm exec vitest run packages/local-db/src/local-db.test.ts -t "initializes foundation schema in WAL mode"
   $rootVersion = (Get-Content -Raw -Encoding UTF8 package.json | ConvertFrom-Json).version
   $desktopVersion = (Get-Content -Raw -Encoding UTF8 apps/merchant-desktop/package.json | ConvertFrom-Json).version
   if ($rootVersion -cne '0.23.2' -or $desktopVersion -cne '0.23.2') {
     throw '候选版本必须为 0.23.2'
   }
   ```

   专项 SQLite 测试必须确认候选代码创建 `Schema 29`，并且
   `schema_migrations` 恰有 29 条迁移。

2. 读取 `E:\AIproject\zyApp\config\public-endpoints.local.json`，严格断言
   `miniappTestApiBaseUrl` 等于 `https://judian.icu/test`，并按上方构建脚本
   将 `miniappTestStoreId` 与 PC 测试环境“设备与门店设置”显示的当前门店 UUID
   逐字符比较；二者不相等时禁止构建或部署。
3. 记录测试 PostgreSQL 当前 `cloud_schema_migration` 最大版本；候选仓库
   `packages/cloud-db/migrations` 的最新迁移必须为 `0018`，Task 7 部署后测试库
   必须达到 18。不得查询或迁移生产数据库来满足此门禁。
4. 记录并保存以下生产基线：生产 API 容器 ID、Caddy 容器 ID、生产健康检查
   HTTP 状态、生产 Windows `release-manifest.json` 的 SHA-256、生产 PC 更新版本。
   同时记录测试 PC 更新版本，但不得修改生产更新目录。
5. 保存 Git 基线：

   ```powershell
   $candidateCommitBefore = (git rev-parse HEAD).Trim()
   $mainCommitBefore = (git rev-parse main).Trim()
   $remoteRefsBefore = @(git ls-remote --refs origin)
   ```

   将三个值写入验收记录。Task 7 只能部署已提交的
   `$candidateCommitBefore`；不得 checkout、合并或改写 `main`，不得 push
   任何远端引用。

## Task 7 发布后复核

发布测试 API、PC 测试更新并完成现场数据核对后，必须逐项与发布前记录比较：

1. 再次断言小程序 API 严格等于 `https://judian.icu/test`，且小程序
   `miniappTestStoreId` 与 PC 测试环境当前门店 UUID 相等。
2. 在更新后的 PC 测试 SQLite 执行：

   ```sql
   SELECT MAX(version) FROM schema_migrations;
   ```

   结果必须为 29；禁止手工修改 SQLite。测试 PostgreSQL 执行：

   ```sql
   SELECT version
   FROM cloud_schema_migration
   ORDER BY version DESC
   LIMIT 1;
   ```

   结果必须为 18。测试发布脚本最终输出必须包含：

   ```text
   Test release healthy: test=0.23.2 migration=18 production=0.22.3
   ```

3. 生产 API 容器 ID、Caddy 容器 ID、生产 Windows 发布清单 SHA-256 必须与
   发布前完全相同；生产健康检查仍为 HTTP 200；生产 PC 更新版本仍为
   `0.22.3`。任何差异都表示隔离失败，必须停止交接。
4. 复核 Git：

   ```powershell
   $candidateCommitAfter = (git rev-parse HEAD).Trim()
   $mainCommitAfter = (git rev-parse main).Trim()
   $remoteRefsAfter = @(git ls-remote --refs origin)
   if ($candidateCommitAfter -cne $candidateCommitBefore) {
     throw 'Task 7 期间候选提交发生变化'
   }
   if ($mainCommitAfter -cne $mainCommitBefore) {
     throw 'Task 7 期间 main 发生变化'
   }
   if (Compare-Object $remoteRefsBefore $remoteRefsAfter) {
     throw 'Task 7 期间远端 Git 引用发生变化'
   }
   ```

   `main` 与全部远端 Git 引用必须保持发布前状态；不得以新建分支、标签或其他
   远端引用绕过“禁止 push”门禁。
