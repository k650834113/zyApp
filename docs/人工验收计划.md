# PC 首版人工验收计划

> 建立日期：2026-06-11  
> 原则：每形成一个完整业务闭环就暂停扩展，先由门店负责人手动验证需求理解。

## 反馈格式

每次验收只需记录：

- 测试编号。
- 实际结果。
- 是否符合门店习惯。
- 希望如何修改。
- 若涉及金额，附操作前后余额。

发现规则理解错误时，先修正规格、测试和当前模块，再继续依赖它的后续模块。

## M2：收费目录和收银

触发条件：收费项目、普通价/高级会员价、现金与储值订单、多人批次和拆单完成。

当前状态：2026-06-11 已达到触发条件，生成 Schema v7 安装包后由用户手动验收。

### M2-01 收费目录与价格快照

1. 店长确认默认入场费普通价 40 元、高级会员价 30 元。
2. 新增一个普通价与高级会员价不同的收费项目。
3. 现金完成一张包含该项目的订单。
4. 返回收费目录修改价格，再回到收银查看近期订单。

预期：新价格立即用于后续订单；旧订单仍显示结账时的名称和价格。

### M2-02 现金与储值独立结算

1. 加入收费项目并现金结账。
2. 重新加入项目，选择一个余额充足的会员后用储值结账。
3. 检查两张消费单订单号和内部访问记录均不同，支付方式分别为现金和储值。
4. 检查储值余额按实收金额减少，赠送余额优先扣除。
5. 用余额不足的会员再次提交储值订单。

预期：每张消费单完全独立且只有一种支付方式；余额不足整单失败并显示“用户余额不足”，不产生订单或扣款。

### M2-03 会员本人入场

1. 查询普通会员，点击入场费项目的“本人入场”并结账，确认实收 40 元。
2. 查询高级会员执行同样操作，确认实收 30 元。
3. 为当天生日会员执行本人入场，确认实收 0 元并显示“生日免费”。
4. 为有效月卡会员执行本人入场，确认实收 0 元并显示“月卡免费”。
5. 暂停该月卡后，在新消费单再次操作，确认恢复正常会员价。

预期：本人入场由系统根据会员等级、生日和月卡状态计算，店员不能手工伪造权益。

### M2-04 再次入场与多人结账

1. 同一会员完成一次本人入场后，在当天新消费单再次本人入场。
2. 确认第二次实收 0 元并显示“再次入场免费”。
3. 跨过自然日零点后再次本人入场，确认按新一天重新计费。
4. 加入多份入场费，分别设置普通价与高级会员价数量。
5. 选择一个会员储值账户统一支付该多人订单。

预期：同一自然日再次入场免费，跨自然日重新计费；多人不要求逐人登记身份；一个会员可一次扣除多人款项。

## M3：退款、凭证和报表

触发条件：退款申请/审批、部分退款、PDF/Excel 凭证和经营报表完成。

当前开发进度：退款和经营报表均已完成开发，并已进入 `0.7.0` 阶段 1C 安装包；执行 M3-A 和 M3-B。

### M3-A C07 阶段性退款验收

1. 店员对现金订单提交部分退款，店长审批后确认应退现金和原订单剩余可退数量。
2. 店员对储值订单提交部分退款，店长审批后确认原会员储值账户增加。
3. 对已交付商品尝试普通退款，再由店长勾选特殊退款并填写原因。
4. 店长分别导出一笔已完成普通订单退款的 PDF 和 Excel 凭证。
5. 店员提交未使用月卡退款，店长审批；再测试已使用月卡的特殊审批。
6. 店员提交现金充值冲正，申请后先发生一笔消费，再尝试审批。
7. 驳回余额已变化的旧申请，按最新剩余本金重新申请并审批。
8. 分别由店长直接完成一笔订单退款、月卡退款和现金充值冲正。

预期：

- 店员只能申请，不能审批或直接退款；店长可审批、驳回和直接处理。
- 月卡超过购买后 24 小时，店长也不能退款。
- 充值冲正只退当前剩余本金，收回未消费赠送金；申请后余额变化时必须重新申请。
- 退款、冲正均生成追加记录，原订单、原充值和原月卡历史不被删除或改写。

重点验证：

- 店员发起、店长审批；店长可直接处理。
- 普通订单退款窗口为完成后 720 小时。
- 现金、储值按原渠道退回。
- 已交付商品仅店长可特殊退款。
- 原订单和原流水不被改写。
- 报表汇总与逐笔流水一致。

### M3-B 营业报表核对

1. 店长进入“营业报表”，选择当天，记录现金实际净流入、订单净销售、充值本金净额和月卡净销售。
2. 新建一笔现金订单和一笔储值订单，刷新报表，确认订单数、渠道净额和项目明细增加。
3. 对现金订单完成部分退款，刷新报表，确认退款按完成日期计入，原订单销售额仍保留。
4. 完成一笔现金充值和一笔充值冲正，确认充值本金、赠送、退款本金和收回赠送分别显示。
5. 购买并退款一张月卡，再使用另一张月卡，确认销售、退款、净销售和使用次数正确。
6. 导出 Excel，确认“营业汇总”和“项目明细”两个工作表与页面金额一致。
7. 使用店员账号登录，确认看不到营业报表入口，且不能导出财务数据。

预期：

- 现金实际净流入等于现金订单净额、充值本金净额和月卡净额之和。
- 储值订单计入订单销售，但不重复计入现金实际净流入。
- 赠送金额不计入现金收入。
- 项目明细使用订单和退款发生时保存的名称、数量和金额快照。
- 报表和 Excel 使用相同日期区间与统计口径。

## M4：备份、恢复和升级

触发条件：自动备份、手动备份、恢复向导、覆盖升级和诊断导出完成。

### M4-A 手动备份和第二目录

1. 使用店长账号进入“备份恢复”，确认页面显示当前数据库路径、Schema、完整性和最近备份。
2. 选择一个新的空目录作为第二备份目录。
3. 点击“立即备份”，确认主备份目录和第二目录都生成 `.db` 与 `.backup.json` 文件。
4. 核对页面显示的文件大小、SHA-256、Schema 和“校验通过”。
5. 使用店员账号登录，确认看不到“备份恢复”，也不能调用备份、恢复或诊断导出。
6. 正常使用超过 6 小时后重新打开页面，确认出现新的自动备份；该项可在日常试运行中补验。

### M4-B 恢复和失败保护

1. 建立测试会员“恢复前会员”，手动创建备份 A，并记录会员数和余额。
2. 再新增“恢复后会员”并完成一笔测试充值，确认当前数据已不同于备份 A。
3. 选择备份 A 执行恢复，确认程序要求确认风险，恢复后清除登录状态并回到登录页。
4. 重新登录，确认“恢复后会员”和后续充值不存在，“恢复前会员”及备份 A 时的数据完整。
5. 确认恢复操作前自动生成 `pre_restore` 保护备份。
6. 尝试选择普通文本、损坏 DB 或高于当前 Schema 的 DB，确认恢复被拒绝且现有数据不变。
