# 小程序已有会员资料分流与头像上传修复设计

> 日期：2026-07-26
> 目标分支：`codex/member-recharge-pc-transactions`

## 背景与根因

上一轮尚未合并的小程序改动增加了会员资料完善页、持久头像和自助资料编辑。实际体验中出现两个互相独立的问题：

1. 头像保存使用 `wx.uploadFile` 请求
   `https://judian.icu/test/v1/member/profile-with-avatar`。微信后台当时只配置了
   request 合法域名，未配置 uploadFile 合法域名，因此客户端直接报
   `uploadFile:fail url not in domain list`。用户已于 2026-07-26 补充该合法域名。
2. 页面使用持久化字段 `profileCompleted` 决定是否进入资料完善页。手机号验证码回退流程还会忽略后端返回的会员结果，无条件进入完善页。该逻辑没有完整表达“本次绑定了已有会员”与“本次创建了新会员”的差异。
3. 2026-07-26 线上探测确认测试 API 对
   `POST /v1/member/profile` 和
   `POST /v1/member/profile-with-avatar` 均返回 404，而同一 API 的
   `GET /v1/member/self` 返回预期的未授权响应。两个资料接口只存在于尚未合并分支，
   表明体验版小程序已先于对应 API 发布，形成客户端与服务端版本不匹配。

## 已确认需求

- 手机号在当前租户会员库中已存在时：
  - 绑定微信身份到原会员；
  - 保留数据库中的昵称、头像、等级、余额、月卡、生日和年龄资格；
  - 不进入名称与头像注册页；
  - 数据库没有头像时显示小程序默认头像。
- 只有本次登录创建了新会员，或该新会员尚未完成首次资料填写时，才进入资料完善页。
- 新会员首次完善资料时昵称必填，头像选填。
- 新会员不上传头像时可使用默认头像完成注册。
- 所有已登录会员均可从“我的资料”修改昵称并上传或更换头像。
- 头像上传失败不得静默丢弃用户选择；首次完善资料时允许用户明确选择使用默认头像继续。
- 不修改钱包、月卡、订单、充值或支付规则。

## 方案选择

采用最小兼容方案，继续使用现有 `profileCompleted` 字段，但收紧其业务含义：

- 已经绑定到当前微信身份且尚未完成资料的新会员，`profileCompleted=false`。
- 本次按手机号命中的既有会员，无论历史 `profileCompleted` 值如何，都视为已有完整会员资料；后端将其修正为 `true`，但不覆盖昵称和头像。
- 本次创建的新会员以占位昵称创建并保持 `profileCompleted=false`，直到昵称保存成功。

该方案不改变现有 `MemberSelfServiceSummary` 响应结构，能兼容当前共享契约、API 和客户端。未采用以下方案：

- 不新增 `existing_member` / `new_member` 登录响应包装类型，因为会扩大共享契约和所有登录调用方改动。
- 不在客户端根据昵称、头像或来源推断新旧会员，因为占位昵称和历史数据不能可靠表示会员创建时机。

## 后端数据流

### 微信手机号一键登录

1. 用微信手机号换取当前租户内的会员记录。
2. 若微信身份已经绑定会员：
   - 返回该会员当前资料；
   - 若其首次资料尚未完成，继续返回 `profileCompleted=false`。
3. 若微信身份尚未绑定、但手机号命中已有会员：
   - 不覆盖已有昵称、头像或其他会员字段；
   - 若 `profileCompleted=false`，追加一次可审计的资料状态修正，将其改为
     `true`；
   - 绑定微信身份并返回原会员资料。
4. 若手机号没有命中会员：
   - 创建新会员；
   - 使用占位昵称和默认空头像；
   - 返回 `profileCompleted=false`。

### 手机验证码回退登录

使用与微信手机号一键登录相同的新旧会员规则。客户端必须读取
`registerMember` 的返回值：

- `profileCompleted=true`：直接进入会员首页；
- `profileCompleted=false`：进入首次资料完善页。

不得再无条件进入资料完善页。

### 资料编辑

- 仅修改昵称时继续使用普通 JSON 请求。
- 选择新头像时继续使用 `wx.uploadFile`。
- 服务端只允许当前已认证会员修改自己的资料。
- 昵称与头像地址、审计记录和同步事件在同一 PostgreSQL 事务中提交。
- 未选择新头像时保留已有头像；没有已有头像时继续使用默认头像展示。

## 小程序交互

### 首次资料完善

- 昵称为必填项，长度继续限制为 2–12 个 Unicode 字符。
- 头像为选填项，页面明确显示“可选，之后可在我的资料中修改”。
- 未选择头像时，保存昵称后直接完成注册。
- 已选择头像但上传失败时：
  - 显示具体错误；
  - 提供“使用默认头像继续”和“返回重试”两个选择；
  - 只有用户选择继续时，才改为仅保存昵称。

### 已有会员与后续编辑

- 已有会员登录后直接进入会员首页。
- 无头像时显示由当前昵称生成的默认头像。
- 首页“编辑”入口继续进入“我的资料”。
- 编辑模式下头像上传失败时保留原资料，不自动降级保存，避免用户误以为头像已更新。

## 合法域名与发布要求

微信公众平台应配置域名根地址 `https://judian.icu`，不填写 `/test`：

- request 合法域名：API JSON 请求；
- uploadFile 合法域名：头像上传；
- downloadFile 合法域名：持久头像展示和下载。

小程序 README、联调文档和发布清单应删除“当前不使用文件上传”的旧说明，并将头像上传、真机显示和域名配置列为发布验收项。

## 测试 API 发布兼容

- 资料接口及数据库迁移必须先发布到隔离测试 API，再上传依赖这些接口的体验版。
- 发布后用无会话请求探测两个 POST 路由；正确结果应为 401
  `Miniapp session is required`，404 `Cannot POST` 表示路由仍未部署。
- 路由烟测通过后，才允许把对应小程序构建交给体验者。
- 本次代码和自动化验证完成后，只部署测试 API；不得据此改动生产 API。

## 生产与开发并行

- `production-wechat` 构建固定访问 `https://judian.icu` 和生产门店；
  构建器拒绝 HTTP、IP 地址和 `/test`。
- `production-test-wechat` 构建固定访问
  `https://judian.icu/test` 和测试门店；构建器拒绝回退到生产根地址。
- 会话存储键包含 API 地址和门店 ID，体验版与正式版不会共享登录令牌。
- 正式版与体验版小程序都保留相同的快捷充值、自定义金额和真实支付流程；
  当前生产 API 仅通过服务端开关保持禁用，正式发布时显式启用。
- 测试 API 发布只构建、迁移并重建 `api-test`，不重启生产 `api` 或
  Caddy。脚本记录两个生产容器 ID，发布后必须保持一致。
- 发布烟测同时检查生产与测试健康状态，并确认两个资料 POST 路由返回
  401 而不是 404。
- 体验版真机验收通过前不合并、不推送 Git。

## 错误处理

- 将 `uploadFile:fail url not in domain list` 转换为用户可理解的中文提示，说明头像上传域名尚未生效。
- 保留 HTTP 状态码和服务端业务错误的现有处理。
- 未授权重试继续复用相同 `requestId`，防止头像资料更新重复执行。
- 上传文件校验继续限制为 JPEG、PNG 或 WebP，最大 2 MiB。

## 测试与验收

### API 定向测试

- 未绑定微信身份按手机号命中已有会员时：
  - 返回数据库原昵称和原头像；
  - 将错误的 `profileCompleted=false` 修正为 `true`；
  - 不创建重复会员；
  - 不覆盖等级、余额、月卡、生日和年龄资格。
- 已绑定但未完成资料的新会员再次登录时仍返回
  `profileCompleted=false`。
- 手机号未命中时创建新会员并返回 `profileCompleted=false`。
- 资料状态修正写入会员事件和审计，事务失败时整体回滚。

### 小程序定向测试

- 微信一键登录与手机号验证码回退登录都按返回的
  `profileCompleted` 分流。
- 新会员只填昵称即可完成注册。
- 头像上传成功后保存持久 URL。
- 合法域名错误被转换为中文提示。
- 首次完善资料选择“使用默认头像继续”时仅保存昵称。
- 编辑模式头像上传失败时不误报保存成功。
- 测试 API 发布后，两个资料 POST 路由从 404 变为预期的 401 未授权响应。
