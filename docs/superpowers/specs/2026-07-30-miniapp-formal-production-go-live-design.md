# 小程序正式环境完整投产设计

> 决策日期：2026-07-30
>
> 状态：已确认，等待执行计划与生产发布
>
> 适用版本：ZyApp 0.23.2

## 1. 目标

将当前 `main` 上已经完成自动化验证的 0.23.2 小程序、NestJS API 和云端数据库能力完整投放到正式环境，使正式小程序可以直接投入使用。

本次投产必须同时解决已经在正式环境复现的头像上传路由缺失，并启用正式微信支付。不能只保留“使用默认头像继续注册”的降级路径，也不能让正式构建继续连接测试环境或使用关闭的支付配置。

## 2. 已确认现状

- 正式小程序构建模式为 `production-wechat`，API 固定为 `https://judian.icu`，正式门店 ID 固定为 `7755df34-4309-43ed-8800-c0dc2049bb17`。
- 当前正式环境对 `POST /v1/member/profile-with-avatar` 返回 HTTP 404，表明正式 API 镜像落后于小程序代码。
- 当前正式 PostgreSQL 的 `cloud_schema_migration` 已达到 18，与仓库最新迁移一致。
- 当前正式环境的 `PRODUCTION_WECHAT_PAYMENT_MODE` 尚未满足 `wechat`，不符合完整正式投产要求。
- 正式环境文件权限、微信 AppID/AppSecret、商户号、证书序列号、微信支付公钥标识和只读密钥文件已通过不泄露内容的检查。
- 正式 API 与测试 API 健康检查均正常。
- 本地候选已完成 96 个测试文件、415 项测试、API 类型检查、API 构建和 `production-wechat` 小程序构建。

## 3. 方案选择

采用“完整正式环境晋升”方案：

1. 保持正式小程序连接 `https://judian.icu`，不切换到 `/test`。
2. 在服务器现有生产环境文件中将正式微信支付模式明确设置为 `wechat`，保留测试环境的独立配置。
3. 使用仓库的正式小程序生产部署流程，发布前执行门店、充赠规则、密钥、双环境健康和数据库状态预检。
4. 发布前生成并校验生产 PostgreSQL 备份。
5. 无缓存重建并重启正式 `api`，应用幂等迁移；除共享入口验证所需范围外，不重建测试 API、测试数据库或 PC 更新通道。
6. 发布后验证头像资料路由、正式支付环境、回调地址、订单前缀、数据库迁移和双环境健康。
7. 保留最终 `apps/miniapp/dist` 为 `production-wechat` 构建，交由账号负责人完成微信开发者工具上传、真机注册、真实支付、商户平台对账、审核和发布。

不采用以下方案：

- 只修头像路由并继续关闭正式支付：不能满足“直接投入使用”。
- 把开发版重新切回测试 API：不能验收正式数据、正式头像卷和正式支付回调。
- 让客户端永久吞掉头像上传错误：会掩盖服务端版本错配，头像功能仍不可用。

## 4. 生产变更边界

### 4.1 允许变更

- 服务器正式环境中的 `PRODUCTION_WECHAT_PAYMENT_MODE`。
- 正式 API 使用的当前仓库源码和容器镜像。
- 正式数据库的幂等迁移执行记录；当前目标版本仍为 18。
- 正式头像持久化卷中的后续会员头像文件。
- 本次正式投产设计、执行计划和发布记录。

### 4.2 禁止变更

- 不把 `/test`、测试门店、测试数据库、测试 Redis、测试头像卷或 `ZYT-` 订单前缀带入正式环境。
- 测试库中的会员、钱包、月卡、订单、支付回调、头像和任何历史数据不得复制、导入、合并、回填或重放到生产库；本次只对生产库执行结构迁移和正式环境自身的业务操作。
- 不启用开发会话、虚拟手机号、Mock 支付或测试金额替换。
- 不覆盖用户现有未跟踪文件 `infra/deploy/production.env.before-domain-20260725`。
- 不删除或改写已有会员、钱包、月卡、订单、支付回调、审计或账本记录。
- 不把 AppSecret、APIv3 密钥、商户私钥、平台公钥或数据库密码写入 Git、日志、聊天或截图。

## 5. 发布前门禁

任一门禁失败即停止发布：

- 工作区候选版本为 0.23.2，自动测试、类型检查和构建全部通过。
- 正式构建只包含 `https://judian.icu` 和正式门店，不包含 `/test`、Mock、开发身份或虚拟手机号。
- 正式环境文件权限为 600，所需微信和支付配置均存在。
- 正式环境恰有一个启用门店，并有有效充赠规则。
- 正式 API、正式迁移服务与测试 API 使用不同的数据库名称；正式迁移服务必须只连接正式数据库。
- 正式与测试健康检查均为 HTTP 200。
- 正式数据库迁移版本等于仓库最新迁移 18。
- 生产支付回调固定为 `https://judian.icu/v1/payments/wechat/recharge/notify`，订单前缀固定为 `ZYP-`。
- 发布前生产备份和 SHA-256 校验成功。

## 6. 发布后自动验收

发布完成必须取得以下证据：

- `GET https://judian.icu/v1/health/ready` 返回 HTTP 200。
- `GET https://judian.icu/test/v1/health/ready` 仍返回 HTTP 200。
- 未携带会话的 `POST https://judian.icu/v1/member/profile` 返回 HTTP 401。
- 未携带会话的 `POST https://judian.icu/v1/member/profile-with-avatar` 返回 HTTP 401，不再返回 404。
- 正式 API 容器内 `DEPLOYMENT_ENVIRONMENT=production`、`WECHAT_PAYMENT_MODE=wechat`、回调地址为正式根域名、订单前缀为 `ZYP-`，且不存在测试金额。
- 测试 API 仍为 `DEPLOYMENT_ENVIRONMENT=test`，使用 `/test` 回调和 `ZYT-` 前缀。
- 测试 API 容器 ID、测试数据库名称和测试数据库迁移版本在正式发布前后保持不变；发布命令不得启动 `migrate-test`、重建 `api-test` 或执行任何测试库数据命令。
- 正式数据库迁移保持 18，生产备份文件与校验文件非空且校验通过。
- 最终小程序产物为 `production-wechat`，只包含顾客正式页面和正式端点。

## 7. 回退策略

- 发布前备份是数据库回退的唯一可信基线；未经确认不自动恢复生产数据库。
- 若新 API 无法健康启动，保留备份和日志，停止小程序上传，不继续真实支付测试。
- 若头像路由仍为 404，视为镜像发布失败，禁止使用默认头像降级冒充验收通过。
- 若环境身份、支付回调或订单前缀错误，立即停止正式测试并恢复正确的环境配置后重新发布；不得让测试订单进入正式库或正式订单进入测试库。
- 已经成功写入的支付、钱包、月卡和账本记录不通过删除回退，只能使用既有幂等、查单、退款或冲正流程处理。

## 8. 负责人真机验收

自动验收完成后，账号负责人依次完成：

1. 在微信开发者工具中确认 AppID、正式 API、正式门店和 `production-wechat` 构建后上传体验版。
2. 使用一个正式环境新手机号注册，选择头像并保存，确认不再出现 `Cannot POST`，退出重进后头像仍显示。
3. 核对会员昵称、手机号、余额、月卡和历史记录均来自正式环境。
4. 选择负责人批准的金额调起微信支付，确认收银台金额一致。
5. 完成一次真实支付，在微信商户平台核对订单、通知和金额。
6. 在小程序、PC 和正式数据库核对本金、赠送、订单及流水均只记录一次。
7. 完成隐私、客服、注销、审核材料检查后提交审核并正式发布。

自动化不能替代真实微信头像上传、手机号授权、真实支付、商户平台对账、微信审核或最终发布确认。
