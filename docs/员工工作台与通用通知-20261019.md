# 员工工作台、现场抽奖报名与通用通知（2026-10-19）

## 已实现范围

- 工作分支 `codex/staff-workspace-notifications`；开发前稳定基线为 PC 0.25.8 / 微信线上1.1.7，稳定标签不变。
- “我的”仅向已绑定且有效的员工显示工作台；首次登录入口为“我的 → 设置与隐私 → 门店员工登录”。沿用员工移动凭据及门店授权，新增 activity.registration.manage、transaction.read；不允许会员自行赋权。后台每次请求重新鉴权，撤销授权后旧令牌也不能访问。
- 工作台可选择PC已配置的抽奖活动，填写1至100人的本批名额，生成默认30分钟的小程序码；报名截止早于30分钟时以截止时间为准。二维码可重复展示、立即作废，再生成会作废该员工同活动旧码。已登记资格不受二维码作废影响。
- 微信扫一扫或小程序“我的 → 扫码报名活动”进入报名页；扫码预留10分钟名额，注册后确认。预留有效期不越过活动报名截止；二维码过期后已有有效预留仍可完成注册确认，作废则阻止未完成报名。名额已满、过期、重复报名等明确提示。
- 同活动扫码每会员只能有一次有效报名，不要求是付款人。消费资格由员工现场核验；不推断订单金额对应人数，不改原PC允许多次人工报名的既有配置。取消保留原因与审计、恢复可用名额；已开奖/报名截止后名单冻结。
- 近期交易默认近30天，支持日期（最多一年）、消费/充值/月卡/退款、姓名/手机号/编号筛选及分页。显示北京时间、会员名、对应项目、金额、赠送、状态与业务编号。消费展示全部订单项目，不沿用会员门票限定；散客显示散客。微信充值以微信订单为来源，不再叠加其钱包账本。PC未同步到云端的交易不能立即显示。只读，不增加财务写入入口。

## 通用消息与微信订阅

- 通知场景、标题/说明、微信模板ID及字段映射由后端保存，店长通过工作台“通知模板配置”维护；支持新增场景，前端通用订阅组件和消息详情页直接复用。
- 首期真正接入 lottery.result；meetup.changed、wallet.changed 为默认未启用的扩展场景，不代表约局/账务事件已经接入。未来后端通过 enqueueMemberNotice 在业务事务中写入消息，不需要为了普通文本消息重做小程序页面。
- wx.requestSubscribeMessage 从按钮事件直接同步触发，订阅票据提前加载；拒绝/失败/模板未配置仍可正常报名。票据按身份、门店、场景、模板和可选业务编号关联；重复回调不能重复增加发送机会，平台才是实际授权权威。
- 开奖与每会员一条结果消息同事务提交，结果仅包含自己的中奖信息。发送与开奖分离，消息中心持久保存，微信发送失败仍可读取。
- 后台定时任务通过 SKIP LOCKED 领取消息与授权，防止并发重复发送；凭证获取失败或平台明确拒绝（忙、限频、令牌失效）有限重试。网络超时/崩溃后结果不明标记 uncertain，不盲目重发。发送状态、次数及错误码留库，不记录密钥。
- 默认模板全部关闭。店长须在微信公众平台选择真实可用模板后配置；映射字段名须与微信模板一致。开奖结果提供 title/result/body/time，time 为北京时间。微信通知仍受一次性授权、平台规则和用户设置限制。
- 新通知沿用通用详情可通过后端扩展；新的业务交互或专用页面仍可能需要小程序发版。
