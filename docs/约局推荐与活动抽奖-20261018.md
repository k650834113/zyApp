# 约局、推荐分类与活动抽奖交付

## 业务操作

1. PC 活动管理选择“报名与抽奖”。活动需先同步到云端；本地未同步活动会提示先同步。
2. 店长填写报名起止、可开奖时间（北京时间）、报名次数与重复中奖选项、规则、奖项和名额。奖项按显示顺序开奖，可用“上移”调整。
3. 工作人员输入完整会员手机号，查找并核对昵称、会员编号，再点击“确认登记一次报名”。允许多次的活动每次确认增加一个机会；网络失败重试同一请求不会重复增加。
4. 首次报名后锁定次数、重复中奖及时间；截止前允许填写原因作废/恢复，恢复仍受单人限次约束。截止后冻结报名和配置。
5. 到达可开奖时间后，店长确认规则、人数及奖项顺序，一次抽完全部奖项。禁止重复中奖时，中奖者的其余机会全部移出；允许重复中奖时仅消耗抽中的机会。空缺保留，不能重抽。
6. 可导出全部报名（含状态、操作员工和变更原因）及中奖名单 CSV，供线下联系、手动发奖。文件按当前 Electron 下载行为保存。

## 接口与部署

- GET /v1/public/meetups/:id?storeId=：可匿名读取分享约局；可选登录状态仅影响本人是否参与、是否发起。展示昵称、头像和会员 ID，不返回手机号及财务信息。
- 约局合同保留 players 昵称数组兼容旧客户端，新增 participants 及 registrationClosed。推荐合同复用 sceneIds，值 two/group 可多选。
- GET /v1/activity-lottery?actorId=&activityId=：读取云端配置、报名、结果。
- GET /v1/activity-lottery/member?actorId=&activityId=&phone=：准确匹配有效会员。
- POST /v1/activity-lottery/commands?actorId=：configure/register/entry-status/draw；携带 requestId、activityId、expectedRevision。版本冲突后刷新核对再操作，网络不确定时使用原请求重试。
- 设备令牌只在 PC 主进程使用，员工身份从当前会话取得；服务端验证员工有效门店权限，配置/开奖仅店长。
- 新迁移 0027_activity_lottery.sql 创建活动状态和操作审计表。先备份并执行迁移，再更新 API、PC，最后验收小程序。发布前确认迁移及 API 成功，因活动公开内容查询会读取新表。
- 云端状态和审计同事务提交，按请求编号及活动加事务锁。操作审计保存命令与结果版本；重复请求返回最新活动状态，避免旧请求覆盖 UI。
- 云端报名数据不写回 PC SQLite；离线不允许报名/开奖。活动最多 20000 条登记、50 个奖项、单奖项 1000 个/总计 5000 个中奖名额。
- 小程序公有活动内容只附带抽奖配置，不包含报名及中奖人员。历史未分类推荐仅展示在全部推荐中，工作人员需补填并发布分类。
